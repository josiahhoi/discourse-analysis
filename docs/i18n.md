# Runtime localization

The app keeps its classic-script architecture and adds no runtime dependencies or
build step. English is the baseline; Simplified and Traditional Chinese are
separate catalogs. The interface language is a local display preference.

## Entry points

- `js/i18n/i18n.js`: locale resolution, lookup, interpolation, DOM bindings,
  change subscriptions and local preference persistence.
- `js/i18n/en.js`, `zh-CN.js`, `zh-Hant.js`: complete message catalogs.
- `js/i18n/relationships.js`: display/search adapter; `DA_PROFILES` remains the
  authority for raw names, canonical IDs, symbols and dominance.
- `js/i18n/relationship-profiles.js`: reviewed profile-specific terminology.
- `js/i18n/native-menu.cjs`: translates existing Electron menu labels while
  preserving roles, actions and accelerators; English restores original labels.

`biblebracket_language` in local storage accepts `system`, `en`, `zh-CN` or
`zh-Hant`. It is never saved in a project, undo history or cloud document.
Follow System uses the primary OS locale in Electron, with the browser locale as
fallback. An explicit Hans/Hant script takes precedence over region. TW/HK/MO
select Traditional; CN/SG/MY and plain `zh` select Simplified; unsupported or
invalid locales select English. Returning to Follow System re-queries the OS.

## Maintaining messages

Add an English key and matching keys in both Chinese catalogs. Existing `s.S####`
keys are stable opaque identifiers; prefer descriptive names for new messages.
English messages may use `{ one: '...', other: '...' }` plural forms. Missing or
malformed translations fall back directly to English using English plural rules.
Interpolation returns plain text and never evaluates HTML.

```js
DA_I18N.t('project.codeCopied', { code });
DA_UI.showTranslatedStatus('relationship.changed', () => ({
  label: DA_RELATIONSHIPS.getName(type)
}), 'success');
DA_I18N.bindValue(element, () => localizedDescription(), 'aria-label');
```

Use `data-i18n` on text-only elements, or a marked span beside icons. Attribute
markers support `title`, `placeholder`, `aria-label`, `data-placeholder` and
`data-drop-label`. Fixed parameters use JSON in `data-i18n-args`.
`apply(root)` handles fragments and template contents; an observer applies
bindings to newly inserted nodes. `bindText` and `bindValue` update mounted nodes
without replacing input fields, drafts or selections. Resolve locale-sensitive
parameters inside callbacks. Never bind user input values or editable content.

Only unchanged builtin relationship names are localized. Custom profile names,
renamed relationships and user labels remain verbatim. The notation editor uses
raw profile values. Search accepts English, both Chinese scripts, original
abbreviations and keywords; IME composition completes before filtering/selection.
Compact Chinese choices retain the original abbreviation even at narrow widths;
the full bilingual name remains available through ARIA, title and focus details.
The reviewed Schreiner terminology is isolated in the profile override file.
Chinese terminology reflects project-specific review, rather than an endorsement
by the notation authors. Relationship explanations preserve the upstream English
support directions; localization does not alter dominance or relationship logic.

Catalogs and profile overrides are independent data files. A language can be
removed by updating the script list, locale choices/resolution, search locales
and native-menu catalog list. The runtime itself uses catalog keys rather than
embedding Chinese text. Retaining English alone requires no project migration.

## Checks

```sh
npm ci
npm run check
npm run test:e2e
node scripts/audit-i18n.cjs
```

The audit also runs through the unit suite. It checks three-way key parity,
explicit source keys and interpolation parameters. Seven documented grammatical
unit omissions allow Chinese fixed units without dropping user data parameters.

`scripts/i18n-source-baseline.json` stores one fingerprint per source file, rather
than a source-text dump. The parser scans JS/CJS string and template literals,
HTML text/accessibility attributes and CSS content. A new, changed, removed or
repeated literal fails the check; line moves and literal reordering do not.
A failure is a review trigger, not automatic proof that the text is visible UI.
Review the file diff, bind new UI messages and verify intentional technical/user
text. Then run `node scripts/audit-i18n.cjs --fingerprints` and manually update only
the reviewed file entries. There is no automatic baseline overwrite command.

Tests use small independent terminology fixtures and ignored Playwright output;
no screenshots, build logs or development evidence are required. OS-owned dialogs,
Services, About metadata and third-party technical errors may follow OS language.
